# Llevar la UI de Ownapp a Figma con Codex

Investigación: 4 de octubre de 2026. Alcance: capacidades publicadas de Figma MCP y experiencias de usuarios; no se realizó una captura ni se midió fidelidad en esta aplicación.

## Respuesta corta

Sí: Figma documenta a **Codex** como cliente de `generate_figma_design`. Esa herramienta captura una **interfaz web en ejecución** y crea frames con capas editables en Figma Design. Es adecuada para trasladar las pantallas web de Ownapp, si primero se ejecutan y se comprueba que representan bien la UI deseada. La captura no importa el código React Native ni convierte una app iOS/Android directamente en diseño; traduce lo que ve el navegador. [Figma: Code to canvas](https://developers.figma.com/docs/figma-mcp-server/code-to-canvas/), [Figma: Codex y Figma, 26/02/2026](https://www.figma.com/blog/introducing-codex-to-figma/).

Hay un segundo camino, `use_figma`: el agente construye y edita frames nativos, componentes, variables y auto layout usando el diseño existente. Figma propone combinarlo con la captura: traer la UI real como punto de partida y después estructurarla con la biblioteca del diseño. [Figma: FAQ del MCP](https://help.figma.com/hc/en-us/articles/39252411778583-Figma-MCP-server-FAQs), [Figma: herramientas MCP](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/).

No asignaría un porcentaje de fidelidad antes de hacer una prueba con una pantalla concreta. Tampoco llamaría «prototipo funcional» al resultado: una serie de frames estáticos no demuestra cámara, OCR, persistencia ni navegación real.

## Cómo lo haría en este repo

1. Tomar como fuente **dos cosas distintas**: la UI implementada y las decisiones de diseño. El [índice de pantallas](../ux/pantallas/README.md) describe seis roles de pantalla y sus estados; la [lámina visual v2](../ux/visual/v2/README.md) y el [sistema de marca](../ux/visual/sistema-de-marca.md) registran la dirección visual. La lámina declara explícitamente que es una propuesta, no una captura de la app. Evitar mezclar sin rótulos «actual», «acordado» y «propuesto».
2. Empezar con **un solo frame de Inicio** y revisarlo antes de ampliar el piloto a selección de sucursal, Captura y Confirmación. Preparar estados reproducibles con datos ficticios y fijar viewport móvil (la lámina usa 360 × 780 unidades de composición). Ejecutar `pnpm web`, comprobar que cada estado se ve bien en navegador y capturarlo por separado cuando corresponda. Figma permite capturar pantalla entera o un elemento y varios estados en una sesión. [Figma: Code to canvas](https://developers.figma.com/docs/figma-mcp-server/code-to-canvas/).
3. En Codex, usar el **servidor MCP remoto** de Figma y pedir la captura a un archivo nuevo o a uno existente. Figma recomienda el remoto; `generate_figma_design` figura como herramienta exclusiva de ese servidor. En un archivo existente, preparar antes las variables si se desea asociación automática. [Figma: introducción MCP](https://developers.figma.com/docs/figma-mcp-server/), [Figma: herramientas MCP](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/), [Figma: Code to canvas](https://developers.figma.com/docs/figma-mcp-server/code-to-canvas/).
4. Inspeccionar frame por frame: tipografía Lexend Deca, colores, medidas, truncado, iconos, imágenes, scroll y superposiciones. La guía actual de `use_figma` advierte una limitación con fuentes personalizadas: verificar Lexend Deca en el resultado y ajustar manualmente si Figma la sustituye. Comparar también con la app en **teléfono físico** para los estados que dependen de APIs nativas. Tratar la cámara y el OCR como estados de diseño con contenido de ejemplo, y verificar su funcionamiento en la app, no en Figma. [Figma: Write to canvas](https://developers.figma.com/docs/figma-mcp-server/write-to-canvas/).
5. Si el resultado visual sirve, usar `use_figma` para convertir elementos repetidos en componentes/variantes y ligar variables; aplicar `figma-use` y `figma-generate-design`, que Figma recomienda para escribir al canvas. Trabajar primero en un draft o copia, como indica Figma para la beta. [Figma: FAQ del MCP](https://help.figma.com/hc/en-us/articles/39252411778583-Figma-MCP-server-FAQs), [Figma: Code to canvas con sistema de diseño](https://help.figma.com/hc/en-us/articles/40287261761559-Code-to-canvas-with-your-design-system).

Prompt de piloto sugerido: «Tomá la lámina `docs/ux/visual/v2/02-inicio-sucursal.png`, `docs/ux/visual/sistema-de-marca.md` y el código de `HomeScreen` como referencias. En un archivo Figma Design nuevo, reconstruí **Inicio habitual** como frame editable de 360 × 780 con texto real, variables de color y auto layout. Ejecutá la app web local para comparar el estado implementado, señalando cualquier diferencia con la lámina propuesta. Revisá visualmente el primer frame, incluida Lexend Deca, antes de continuar con las demás pantallas».

## Qué dicen fuentes directas y usuarios

- **Figma, 26/02/2026:** Yarden Katz, product manager, presenta explícitamente el flujo Codex → interfaz en ejecución → `generate_figma_design` → frames editables. También plantea editar en Figma y volver al código con el contexto del frame. Es una descripción de producto, no una prueba independiente de fidelidad. [Artículo original](https://www.figma.com/blog/introducing-codex-to-figma/).
- **Dylan Field, CEO de Figma, 17/02/2026:** defiende usar el canvas para comparar opciones y salir de la vista lineal de un prototipo codificado. Es una orientación estratégica útil para organizar variantes y recorridos, no una garantía técnica de conversión. [Artículo original](https://www.figma.com/blog/the-future-of-design-is-code-and-canvas/).
- **Foro oficial, Dave Ackerman, 25/02/2026:** relata que `generate_figma_design` le produjo geometría editable sin instancias de los componentes publicados ni variantes; en abril otra participante sugiere `use_figma` para reemplazar esos frames por recursos de biblioteca. La limitación coincide con la FAQ oficial actual; el caso concreto sigue siendo anecdótico. [Hilo](https://forum.figma.com/suggest-a-feature-11/figma-mcp-generate-figma-design-should-resolve-html-elements-to-existing-library-components-instead-of-raw-frames-51286).
- **r/FigmaDesign, mayo-junio de 2026:** un hilo de uso del agente de Figma reporta resultados lentos y desiguales; otro usuario dice obtener mejores resultados cuando el archivo ya tiene assets y variables, y recomienda trabajar con un frame por vez. Son experiencias individuales con herramientas y proyectos distintos; sirven como hipótesis para el piloto, no como benchmark. [Hilo](https://www.reddit.com/r/FigmaDesign/comments/1tk53ap/figmas_ai_agent_an_honest_review/).

## Decisión recomendada

Empezar con un frame de Inicio y juzgar dos resultados por separado: (1) semejanza visual con la dirección que se quiere representar y (2) calidad estructural del archivo Figma. Si falla la primera, ajustar el frame con `use_figma` desde la dirección visual acordada. Si falla la segunda, usar la captura web como referencia y crear componentes/variables nativos. Ampliar después a los otros tres estados; la selección de método para el resto de pantallas depende de esa comparación real.
